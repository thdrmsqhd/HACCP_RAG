# HACCP 도우미 프로토타입 (v0)

문제정의(`../01_문제정의.md`)의 **품질 담당자** 축 MVP. LLM·임베딩 없이 **고시 조문 검색 + CCP CSV 조회**만으로 3단 답변을 낸다.

## 실행

```bat
cd C:\Users\gbsong\Documents\HACCP_RAG\prototype
python cli.py                      :: 예시 질문 4개
python cli.py "인증 신청 서류는?"   :: 특정 질문
python eval.py                     :: 평가셋 채점
```

의존성 없음(파이썬 표준 라이브러리만).

## 구성

| 파일 | 역할 |
|---|---|
| `corpus.py` | 고시 텍스트 → 조문 단위 파싱 (36개 조문, 교차 인용 필터링) |
| `retrieve.py` | 단어 TF-IDF + 제목 가중 + 동의어 확장 검색 |
| `ccp.py` | CCP CSV(10,527건) 정형 조회 + 표기 정규화 |
| `cli.py` | 라우팅(서술/정형) + 3단 답변 생성 |
| `eval.py` | 평가셋 10문항 자동 채점 |

## 답변 형식

```
[설명] 근거 조문에서 질문과 가장 관련된 문장
[근거] 「식품 및 축산물 안전관리인증기준」 제N조(제목)
[단계] 1~5단계 중 어디
[다음 할 일] 체크리스트 한 줄
```

## 현재 성능 (2026-11-12 기준)

**튜닝셋 10문항** (문항을 보며 규칙을 조정한 셋)

| 방식 | Top-1 | Top-3 |
|---|---|---|
| 키워드 TF-IDF | 6/10 (60%) | 9/10 (90%) |
| 하이브리드 (임베딩 0.6 + 키워드 0.4) | 9/10 (90%) | 10/10 (100%) |
| 임베딩 단독 (alpha=1.0) | 3/10 (30%) | 5/10 (50%) |

**홀드아웃 20문항** (튜닝에 미사용 — 이 수치가 실제 성능)

| 방식 | Top-1 | Top-3 |
|---|---|---|
| 키워드 | 12/20 (60%) | 18/20 (90%) |
| **하이브리드** | **13/20 (65%)** | **19/20 (95%)** |

- 튜닝셋 90%는 **과적합**이었다. 하이브리드의 실제 기여는 +5%p.
- 임베딩 모델: `paraphrase-multilingual-MiniLM-L12-v2` (384차원, fastembed/ONNX)
- 임베딩 단독은 더 나빠서 하이브리드로 확정.
- 정형 질의(CCP): 살균 57건 → CCP-1B 우세 등 정상 동작

재현:
```bat
uv run --with fastembed python build_embeddings.py
python holdout_eval.py kw
uv run --with fastembed python holdout_eval.py emb 0.6
```

## 웹 UI (데모)

```bat
python server.py      :: http://127.0.0.1:8765
```

- 5단계 카드(대상 판단 → 선행요건 → 계획 → 신청 → 유지) 클릭 시 예시 질문 자동 입력
- 답변은 **설명 / 근거 / 다음 할 일** 3단 + 검색된 출처 칩(고시=회색, 매뉴얼=주황)
- LLM: 로컬 Ollama `hermes-test-qwen38-9b:q4` (외부 API 키 불필요)
- **스트리밍**: 근거 칩은 즉시(0.0~0.3초), 답변 완료 7.7~19초 (평균 14초)

| 개선 | 내용 | 효과 |
|---|---|---|
| 인덱스 캐시 | 프로세스 1회 생성 | 0.21초/요청 절감 |
| 모델 워밍업 | 기동 시 예열 + `keep_alive=30m` | 콜드스타트 35~40초 제거 |
| 스트리밍 | `/api/stream` | 체감 대기 0.3초 |
| BM25(매뉴얼) | TF-IDF 대체 | 매뉴얼 Top-1 88% → **100%** |
| 조문 필터 | 포함률 0.34 + 항 단위 분해 | 무관 조문 인용 제거, 숫자 규정 정확도↑ |

## 답변 정확성 평가

```bat
python answer_eval.py            :: 30문항 실행 → answer_eval_results.jsonl
python answer_eval_failures.py   :: 실패 사례만 출력
```

| 항목 | 값 |
|---|---|
| 정답 | 22/30 (73%) |
| 출처 일치 | 19/30 (63%) |
| 근거 없는 수치(환각) | 0건 |
| 평균 응답 | 24.4초 |

- **수치 가드**: 답변의 `숫자+단위`를 근거 문장과 대조, 불일치 시 엄격 프롬프트로 1회 재생성
- **조문 항 단위 분해**: 제20조(교육시간)처럼 한 조문에 숫자가 여러 개일 때 정확도 확보

## OCR (평가매뉴얼 609쪽)

| 항목 | 값 |
|---|---|
| 엔진 | easyocr (ko+en, CPU) |
| 속도 | 5.4초/쪽 → **609쪽 전체 53분** (완료) |
| 결과물 | `manual_ocr/page_0001~0609.txt` (4.9MB), bbox JSONL |
| 청킹 | **페이지 단위** (항목 단위는 OCR 잡음으로 경계 붕괴) |
| 보정 | `manual_index.clean()` — 빈출 오인식만 치환 |

**검색 품질 (매뉴얼 8문항)**

| 지표 | 값 |
|---|---|
| 페이지 번호 일치 Top-1 | 3/8 (38%) ← 업종별 반복 때문에 과소평가 |
| **정답 문구 포함 Top-1** | **7/8 (88%)** |
| 정답 문구 포함 Top-3 | **8/8 (100%)** |

> 매뉴얼은 같은 평가항목이 업종별로 반복된다. “정확한 페이지 번호”를 맞히는지는 유용성과 무관하므로
> **답이 되려면 포함돼야 하는 핵심 어구** 기준(`manual_eval_phrase.py`)으로 측정했다.

```bat
uv run --with easyocr --with pymupdf python ocr_pdf.py 1 609
python search_all.py "청결구역 출입 복장 기준"
python manual_eval_phrase.py
```

## 알려진 한계

1. **“인증 후 교육” 질의**에서 제21조(교육훈련기관 지정)로 오검색 — 제20조(교육훈련)와 어휘가 겹침. 임베딩·리랭커로 해결 필요.
2. **평가매뉴얼(609쪽) 미포함** — 스캔본이라 OCR 전에는 검색 불가.
3. **CSV 표기 불일치** — `CCP 2P`, `CCP2P`, `CCP-2P` 혼재. 정규화로 처리했으나 위해요소 표기는 여전히 흔들림(`금속성이물`/`금속성 이물`).
4. **답변 문장이 조문 원문 그대로** — 요약·쉬운 말 변환은 LLM 단계에서.
5. **부정 케이스 미구현** — “인증받을 수 있나요?”에 판정하지 않는 로직은 LLM 프롬프트 단계에서.
