# HACCP 문서 근거 검색 도우미

HACCP을 처음 도입하는 **품질 담당자**가 “누구에게 묻지 않고” 다음 할 일을 파악하도록 돕는 사내 도구입니다.
답변은 항상 **① 설명 → ② 근거 조항 → ③ 다음 할 일** 3단으로 나오고, 근거는 고시 조문과 평가매뉴얼 페이지로 표시됩니다.

> 컨설턴트를 대체하지 않습니다. 최종 판단과 승인은 담당자가 합니다.

## 해결하려는 문제

| 페르소나 | 지금 겪는 일 |
|---|---|
| 공장 품질 담당자 | 인증을 준비해야 하는데 무엇부터 해야 하는지 모름. 사내에 경험자 없음 |
| 도메인 진입 개발자 | HACCP 용어·절차를 문서마다 다시 찾아봄 |

기존 문서는 **읽기 위한 문서**입니다. 필요한 순간에 “지금 내가 뭘 해야 하는지”를 꺼내주지는 않습니다.

## 구성

| 소스 | 규모 | 성격 |
|---|---|---|
| 식품 및 축산물 안전관리인증기준 고시 | 36개 조문 (42,509자) | 법적 근거 |
| HACCP 평가심사 매뉴얼 | 609쪽 (OCR) | 평가항목 해설 |
| 업종별 중요관리점 정보 | 10,964행 CSV | 정형 조회 |
| 자사 문서 | 미확보 | 현장 절차(차별점) |

## 설계 결정

**1. 검색기를 소스별로 분리했다**
- 고시 36조문 → 임베딩+키워드 하이브리드
- 매뉴얼 609쪽 → BM25 키워드

측정 결과가 반대였기 때문입니다. 매뉴얼은 OCR 잡음과 업종별 반복 구조 때문에 임베딩이 오히려 나빴습니다(75% vs 88%). “임베딩이 항상 낫다”는 가정을 데이터로 버렸습니다.

**2. 평가 지표를 두 번 갈아엎었다**
- 처음엔 “정답 페이지 번호 일치”로 채점 → 60쪽일 때 75%, 609쪽에서 38%로 급락
- 원인은 **같은 평가항목이 업종별로 반복**되는 매뉴얼 구조. 페이지 번호는 유용성과 무관
- → “답이 되려면 포함돼야 하는 **핵심 어구**” 기준으로 재정의

**3. 부정 결과를 지우지 않았다**
- 튜닝셋 90% → 홀드아웃 65%: 과적합 확인
- 섹션 메타데이터 부스트/하드필터: 60%/95% → 35%/70%로 **역효과**
- 이 기록이 “왜 안 했는가”에 대한 답이 됩니다

**4. 답변은 생성이 아니라 인용이다**
- 프롬프트에서 근거 외 내용 금지, 출처 표기 강제
- 무관한 조문이 붙지 않도록 조문 유사도 하한(0.08) 적용

## 실측 결과

| 항목 | 결과 | 조건 |
|---|---|---|
| 고시 검색 (키워드) | Top-1 60% / Top-3 90% | 홀드아웃 20문항 |
| 고시 검색 (하이브리드) | **Top-1 65% / Top-3 95%** | 홀드아웃 20문항 |
| 매뉴얼 검색 (BM25) | **Top-1 100% / Top-3 100%** | 8문항, 핵심 어구 기준 |
| 매뉴얼 OCR | 609쪽 / 53분 / 5.4초·쪽 | easyocr CPU |
| 응답 지연 | 첫 화면 0.3초, **완료 22.8초**(비캐시) / 반복 0초 | 로컬 9B Q4, CPU |
| **답변 정확성** | 튜닝셋 93%(28/30) · **새 홀드아웃 정답 53%(8/15), 오답 0, 정답+부분 100%** | 자동/사람 채점 |
| 환각(근거 없는 수치) | **0건** | 수치 가드 적용 후 |
| 검색 (조문) | Top-1 45% / Top-2 65% | 홀드아웃 20문항, 2단계 검색 |

평가셋은 직접 작성했습니다. 규모가 작고(8·20·30문항) 저자 편향이 있으므로 **일반화 수치로 읽으면 안 됩니다.**
답변 정확성은 토큰 포함 여부로 자동 채점해 의미 일치를 완벽히 대표하지 못합니다(부분 1건 포함).

## 한계

- **절차·주체형** — 유형 라우팅으로 오답 0까지 개선. 단 답이 ‘부분’에 머무는 경우가 많음(출처만 가리키는 요약)
- **자사 문서 미확보** — 공개자료만으로는 “현장 절차” 차별점이 없음
- **운영 요건 없음** — 인증·권한·감사로그 미구현
- **속도** — 평균 22.8초(비캐시). 프롬프트 처리 32 tok/s가 한계라 근거를 150자 문장 단위로 압축
- **OCR 품질** — 오탈자 존재(`을→올`, `작업→직업`). 빈출 패턴만 보정

## 실행

```bash
# 검색 데모
python prototype/search_all.py "청결구역 출입 복장 기준"

# 웹 UI (LLM 포함)
python prototype/server.py        # http://127.0.0.1:8765
```

필요 환경:
- Python 3.11
- OCR: `uv run --with easyocr --with pymupdf python prototype/ocr_pdf.py 1 609`
- LLM: Ollama + `hermes-test-qwen38-9b:q4` (없으면 `answer.py`의 `MODEL` 변경)
